# Word 与图片处理

## Word

- `.docx`：优先使用墨布现有的 `src/word-import.js` 转换逻辑，或使用 Documents skill 读取后生成等价 Markdown。
- `.doc`：当前墨布只给出旧格式警告，不应假装已可靠转换；要求用户另存为 `.docx`。
- 墨布现有转换基于 Mammoth + Turndown + GFM，可保留标题、粗体、链接、列表、表格与内嵌图片；首行表格单元应作为表头。
- Word 样式名和字号只是候选证据。正文语义、目录结构和上下文优先于“看起来更大”。
- Word 内嵌图片的锚点/出现位置应记录为图片初始位置；若另有同名外部高清图，比较内容后优先用清晰版本，并在确认面板说明替换关系。

## Markdown

- 保留 YAML frontmatter（若存在），但墨布正文从 frontmatter 后开始分析。
- 已有合法墨布标记优先保留；发现多个 `#`、多个 `@subtitle`、跳级标题或失效图片路径时，在确认面板标记。
- 不把 HTML/CSS 大段重写成 Markdown，除非用户明确要求；先说明墨布复制结果可能依赖这些内联样式。

## 图片

- 支持以真实文件内容为准的 PNG、JPEG、GIF、WebP、SVG、AVIF；扩展名与内容明显不符时先报告。
- 需要判断画面语义时直接查看图片；不要只凭文件名猜。
- 先按像素或文件哈希识别重复图。相同内容只选清晰度更高且格式适合的一份，其他列入“暂不使用”。
- 横向大图通常是头图候选，竖图或方图通常是正文图候选，但比例只是弱证据。
- 动图、透明图或 SVG 不做破坏性转码。透明图片必须保留真实 Alpha 通道。
- 不裁剪、不压缩、不改色，除非用户另行提出并确认。
